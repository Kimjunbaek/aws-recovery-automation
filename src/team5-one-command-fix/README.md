# 한 줄 통합 대응 보완

현재 서비스는 수동으로 ALB 전환을 마무리한 복구 서비스입니다. 이전 자동화 실행 기록은 FAILED이며, 이 업데이트가 그 기록을 성공으로 바꾸지는 않습니다.

## 한 번만 적용하는 업데이트

프로젝트 계정 123456789012의 서울 리전 CloudShell에 ZIP을 업로드한 다음 실행합니다.

```bash
unzip ~/team5-one-command-fix.zip -d ~/team5-one-command-fix-package
cd ~/team5-one-command-fix-package/team5-one-command-fix
python3 setup.py prepare
```

정의 검증이 통과하면 적용합니다.

```bash
python3 setup.py apply
```

prepare는 조회와 로컬 백업만 수행합니다. apply는 새 SSM 문서 버전, 복구 워크플로우, CloudShell의 기존 실행/복귀 도구를 수정합니다. 격리, 복원, 프록시 연결 변경, ALB 전환, 리소스 삭제는 실행하지 않습니다. 기존 문서 버전과 설정 백업을 보존합니다.

## 이후 사고 대응 시작 명령

```bash
python3 ~/team5-bastion-integration-package/team5-bastion-integration/run-response.py execute
```

기존 웹·운영 배스천 대응을 시작하는 수동 트리거입니다. 위협 탐지 시스템에서 자동으로 호출되는지까지 검증한 명령은 아닙니다.

기존 병렬 배스천 대응 및 웹 EC2/RDS 복원 흐름을 유지하고, 웹은 기존 ProxySQL을 거쳐 새 RDS에 접속합니다. 이번 수정은 웹 검증에 직접 RDS 접속을 요구하지 않으며, ALB 전환 후 일반 요청에서 HTTP 200과 예상 제목을 3회 연속 확인한 뒤 기존 active 태그 단계로 진행합니다. 일시적인 503은 제한된 횟수 안에서 재검사합니다. 최종 검사 실패 시 자동으로 격리를 해제하거나 프록시·ALB를 되돌리지 않습니다.

## 지금 execute를 다시 실행하지 않는 이유

현재 복구 웹과 새 RDS가 서비스를 제공하고 있습니다. 초기 상태 복귀와 재시험 준비 없이 다시 실행하면 운영 자원과 충돌할 수 있습니다. 새 사전 점검은 원래 웹·배스천의 정상 보안 그룹, 기존 웹으로 향하는 ALB, 비어 있는 복구 대상 그룹, 기존 RDS 한 대, 유효한 지정 백업, 기존 RDS를 향하는 프록시와 이전 전환 잠금 해제를 확인합니다. 충족하지 않으면 격리 전에 중단합니다. RDS 한 대 조건은 이 프로젝트의 두 대 한도 테스트 준비 조건이며 AWS 공통 제한을 의미하지 않습니다.

이 패키지는 현재 복구 서비스나 DB를 자동으로 삭제하여 초기화하지 않습니다. 복귀 도구는 현재 워크플로우에 지정된 새 웹 검사 문서를 사용하도록 수정하지만, 기존 서버 격리 해제·배스천 복귀·자원 정리까지 자동 수행하지는 않습니다.

## 검증 범위 및 남은 사항

- 로컬 테스트 8개: 상태 연결, 반복 적용, 503 재검사, 연속 성공 조건, 제목 불일치, 직접 DB 접속 요구 제거, 실행 도구 패치 검증.
- AWS 정의 검증은 CloudShell prepare/apply에서 수행합니다. 실제 통합 실행 성공은 아직 검증하지 않았습니다.
- 배스천의 실제 Prometheus 수집은 별도로 확인해야 합니다.
- 백업은 고정 참조입니다. 최신 백업 자동 선택 기능은 추가하지 않습니다.
- 원본 웹과 배스천 ID를 지정한 현재 시나리오용입니다. 이후 새 서버를 운영 원본으로 승격한 다음 사고 대응 대상을 자동 추적하는 기능은 포함하지 않습니다.
- 기존 태그 단계의 실패 처리 정책은 유지됩니다. 대시보드 태그 실제 반영은 실행 결과에서 확인합니다.
- 기존 CloudFormation/배포 패키지를 다시 적용할 때는 이번 수정과 기존 태그·백업 변경을 함께 반영해야 합니다.

소스: setup.py는 설정 업데이트, web_worker.py는 SSM 웹 검사, one_command_preflight.py는 실행 전 점검입니다. expected-v2-worker.py는 현재 배포 코드의 예상 원본 비교용입니다.
